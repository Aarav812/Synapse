## 2025-02-23 - Throttle heavy DOM updates during streaming
**Learning:** Calling heavy synchronous functions like `renderMarkdown` which parse strings through multiple regex passes and directly cause layout thrashing (`scrollToBottom`) inside high-frequency loops like processing single network chunks from Server Sent Events (SSE) will cause O(n²) rendering complexity. This specifically creates severe input lag and UI jank in long responses because string chunk processing occurs more frequently than browser repaint cycles.
**Action:** Throttle continuous rendering paths and `scrollToBottom` updates during streams with `Date.now() - lastTime > delayThreshold` (e.g., 32ms) so the main thread yields correctly and the heavy rendering pass doesn't execute hundreds of unnecessary times per second. Always ensure the final render captures everything post-stream.
