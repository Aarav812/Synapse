## 2024-05-24 - Debouncing Synchronous localStorage reads
**Learning:** In this architecture, `localStorage` is used synchronously to fetch the conversation history index (`getHistoryIndex`). When filtering this history (e.g., via the search input in the sidebar), the previous implementation triggered a full read of `localStorage` and a complete DOM rebuild of the history list on *every single keystroke*. Since both `localStorage` access and DOM manipulation are synchronous blocking operations on the main thread, this created noticeable UI jank for users with a large chat history.
**Action:** Always wrap event listeners that trigger synchronous storage reads or heavy DOM updates (like search inputs) with a debounce function. This ensures the heavy operations only run once the user has paused typing, keeping the UI responsive.
